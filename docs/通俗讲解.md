# WinPilot 通俗讲解（零基础版）

> 这份是给"之前没怎么接触过 AI agent"的你准备的。全程大白话 + 打比方,先把它讲明白,
> 你能照着给面试官讲清楚就够了。更专业的细节在 `docs/架构与设计.md`,这份先看。

---

## 一、它到底是个啥?(一句话 + 比方)

**WinPilot 是一个"会自己操作 Windows 电脑的 AI 助手"。**
你用一句话告诉它要干嘛(比如"打开记事本写句话存到桌面"),它就**自己去点鼠标、敲键盘、开程序**,把事办了。

**打个比方**:它就像你雇了一个**远程实习生**——
- 你发个微信:"帮我把那个文件夹建好";
- 实习生**看着屏幕**、**自己动手**操作你的电脑,办完跟你说"好了"。

这个"实习生"的大脑是一个 **AI 大模型**(就是类似 ChatGPT 那种)。

---

## 二、先扫盲几个词(面试可能蹦出来)

| 词 | 大白话 |
|---|---|
| **大模型 / LLM** | 会聊天、会推理的 AI(像 ChatGPT)。我们用的是个便宜款叫 deepseek。 |
| **Agent(智能体)** | 不只是聊天,还能**自己动手干活**的 AI。会聊天的是"嘴",Agent 是"手脚都有"。 |
| **工具(tool)** | 我们给 AI 准备的一组"动作按钮":点击、打字、截图、开程序……AI 想干啥就"按"哪个。 |
| **computer-use** | "让 AI 直接操作电脑"这个方向的统称。 |
| **多模态** | AI 能"看图"。我们这个模型**不会看图**,所以才有了下面的巧思。 |

---

## 三、最大的难题,和我的巧思

我们用的这个 AI **是个"瞎子"——它不会看图、看不见屏幕**。
那它怎么知道屏幕上有啥、该点哪儿?

**我的核心做法:不让它"看",而是把屏幕"读"给它听。**

打个比方:
> 屏幕就像一幅画。普通做法是把整幅画拍照给一个"能看画的 AI"。
> 我的做法是:派几个**助手**先把画**翻译成一份文字清单**,再念给"瞎子 AI"听:
> 「第 1 个:保存按钮,在坐标 (842,615);第 2 个:文字'无标题',在 (120,18)……」
> AI 听完就知道"哦,保存按钮在 842,615",直接说"点第 1 个"。

这几个"翻译助手"就是 **多维感知**(下一节细说)。

**为什么这么干?** 因为:
- 便宜模型不会看图;
- 就算会看图也慢、贵、还点不准;
- "读成文字清单"又快又准,还能告诉你"这个信息是哪个助手提供的"(方便排错)。

---

## 四、它怎么"看"屏幕(多维感知)

派 4~5 个助手,各有各的本事,**互相补盲**:

```
            ┌─────────────────────────────┐
            │   一个窗口(比如记事本)        │
            └──────────────┬──────────────┘
                           ▼
   ┌────────┬────────┬────────┬────────┬────────┐
   │ UIA    │ Win32  │ OCR    │ OpenCV │ VLM(可选)│
   │控件树   │老式控件 │认字    │认图标   │看图AI   │
   └────────┴────────┴────────┴────────┴────────┘
                           ▼
          【合并去重,排掉重复的】
                           ▼
   一份文字清单:[1] 按钮"保存" (842,615) ...
```

- **UIA**:Windows 自带的"无障碍接口",直接问系统"这窗口有哪些按钮/输入框",**最准**。
- **OCR**:认屏幕上的**文字**(就像扫描仪认字)。
- **OpenCV**:认**图标**这种没文字的东西。
- **VLM**:真正"看图"的 AI(用的小米 MiMo),**平时不开**,只在前面几个都瞎了才兜底。

**几个亮点(面试可以说):**
1. 每条信息都标了"哪个助手提供的",出问题好排查;
2. 一个助手够用就跳过慢的(比如 UIA 已经报了一堆,就不浪费 6 秒去 OCR);
3. 如果**全瞎了**(啥都没读到),才升级用更贵的手段——不会一上来就用慢的。

> ⚠️ 它**只读最前面那一个窗口**,不是整个屏幕。之前你看到"识别到 70 多个元素"——那不是读多了,是 Krita 那个画图软件**本身按钮就特别多**。换记事本就几个。

## 五、它怎么"动手"

给 AI 一组"按钮"(工具),它想干啥就按哪个:
- `点击`、`打字`、`快捷键`、`滚动`、`拖拽`
- `打开程序`、`列出窗口`、`运行命令行`
- 还有特殊的:`截图问 AI`、`记住这件事`、`复用上次的做法`……

**怎么动手最稳?** 优先用"无障碍接口直接调"(相当于不用鼠标、直接命令按钮"你给我按下"),实在不行才真的移鼠标点。

> 这也是你要的「**不夺光标**」功能的基础:能不动你鼠标就不动——后台悄悄点;万一非得用鼠标,点完**立刻把光标弹回你原来的位置**。

---

## 六、它怎么知道"到底做成没"(这是精华)

AI 经常**自我感觉良好**——明明没做成,却说"我做完了"。这在 GUI 里特别坑。
我用了**三道关**,层层把关:

```
做一步  → 第1道:这一步做完检查一下(比如"另存为"窗口出现了吗?文件真在硬盘上吗?)
做完了  → 第2道:它说"完成"时,先别信!重新看一眼真实屏幕 + 查硬盘证据,
                 派"另一个 AI 当考官"问:"真做完了吗?" 没做完就打回去继续。
事后    → 第3道:专门的"考试系统"用程序去查硬盘/进程,客观判分,绝不听 AI 自己说。
```

**打比方**:
- 第1道 = 写一行作业就核对一下;
- 第2道 = 交卷前老师抽查一遍;
- 第3道 = 期末统考,机器阅卷,不看你自己感觉。

> "查硬盘上文件真的在不在"这种**铁证**,比"看屏幕猜"靠谱得多——这是这个项目最 Codex 级的地方。

---

## 七、它怎么"越用越聪明"(记忆 + 复用)

```
某个任务成功了(且通过了上面的核验)
        │
        ▼
把这次的步骤记成一份"菜谱"(还自动存成一个可重放的脚本)
        │
        ▼
下次遇到几乎一样的任务 → 直接"照菜谱重放",几乎不花钱、不用重新想
```

**打比方**:第一次做番茄炒蛋要边查边做;做成功后记下菜谱;下次直接照着做,又快又稳。
- 防坑:**只有真做成的才记**(没做成的不许记成"经验",免得越学越歪);
- 菜谱记的是"点【保存】按钮"这种**意图**,不是死记坐标(换个屏幕分辨率也能用)。

---

## 八、怎么证明"我改了之后是变好不是变坏"

这是面试加分项。我做了一套**自动考试系统(eval)**:
- 准备一组**真实任务**(建文件夹、开计算器算 12×34、克隆代码、记事本存盘……);
- 每个任务配一个**铁面判分员**(去查硬盘/进程,不听 AI 自夸);
- 每次我改完代码,跑一遍考试,看**通过率、用了几步、花了多少钱**有没有变好。

**实际效果**:它真帮我抓到过两次"我以为改好了其实改坏了"的情况,我才修对。
→ 面试就说:"我不靠感觉,我靠这套 eval 用数字说话。"

## 九、完整走一遍(例子:打开记事本写字存桌面)

```
你: "打开记事本,输入'你好',另存为到桌面 test.txt"
 │
 ├─ AI 先想:这是多步任务 → 列个待办:①开记事本 ②输入 ③另存为
 ├─ ①开记事本 → 用"打开程序"工具 → 检查:记事本窗口出现了✓
 ├─ ②读屏幕(感知)→ 找到编辑区 → "打字"工具输入"你好" → 检查✓
 ├─ ③按 Ctrl+S → "另存为"窗口弹出 → 在文件名框输完整路径 → 回车
 ├─ AI 说:"做完了 done"
 ├─ 🚦把关:重新看屏幕 + 查硬盘"桌面/test.txt 真的在吗?内容对吗?"
 │        → 在!内容对! → 通过
 └─ 记成菜谱 + 存可复用脚本 → 告诉你"完成"
```

## 十、面试就这么讲(背下来这几句)

1. **它是什么**:"一个能自己操作 Windows 的 AI 助手,你说句话它就帮你点鼠标敲键盘把事办了。"
2. **最大难点+我的解法**:"我用的 AI 不会看图,所以我把屏幕用多种方式**读成文字清单**喂给它,而不是截图。"
3. **最得意的设计**:"我不信 AI 自己说'做完了'——用**查硬盘/进程的铁证**和**第二个 AI 当考官**来核验,专治'假完成'。"
4. **工程素养**:"我做了一套**自动考试系统**,每次改代码都用真实任务+客观判分来确认没改坏,而不是凭感觉。"
5. **会取舍**:"该做的我做了(验证、记忆、规划);**不该做的我主动没做**——比如有个'给 AI 装一堆工具再用向量搜索挑工具'的流行做法,我算过对我这个规模是负优化(会拖慢、变贵),就没做。"
